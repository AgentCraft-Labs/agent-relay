AgentRelay 0.4.1 adds a managed macOS bridge for the unchanged official Codex app. Codex retains its built-in `openai` provider identity while genuine native child agents still execute Claude Code or another configured CLI. The inspected desktop implementation therefore suppresses the custom-provider row under the account menu, without blank-name tricks, app patches or an intermediate model.

Upgrade with `./agentrelay codex upgrade --wait-idle`, then activate with `~/.agents/skills/agentrelay/scripts/agentrelay codex migrate` while workers are idle. Migration switches configuration only after both listeners are ready and restores previous settings/service on failure. Historical chats retain their compatible provider definition, native identities and external sessions; chat databases/rollouts are not rewritten. `codex rollback` restores earlier routing while preserving later unrelated preferences. Later upgrades retain the selected mode.

Both listeners run in the same companion process. The guardian checks both endpoints and their PID agreement, recovers unloaded registrations and restarts only a verified repeatedly unresponsive provider. HTTP/SSE, bounded Zstandard decoding and cancellation are preserved. Local admission uses the macOS UID, actual executable and TCP socket tuple; URLs contain no admission secret. Migration also registers the native Codex CLI found on PATH, with repeatable `--also-codex-bin` for additional native targets. An unavailable optional CLI cannot stop desktop chats. Scripts and non-native files cannot authorize a peer. Native wrapper compaction now stores an opaque local checkpoint without consuming a prepared task or launching another model.

Download `macos-arm64` for Apple Silicon or `macos-x86_64` for Intel, verify the SHA-256 file and follow the README. This companion provides no OS sandbox, and a forced restart can interrupt active work; persisted sessions remain available for explicit follow-up without automatic task replay.
